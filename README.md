# RiskLens AI

**RiskLens AI** is an explainable payment-risk detection prototype for hackathon demonstration. It ingests transaction attributes, predicts a fraud probability, combines that probability with transparent behavioral risk signals, and returns a risk score, risk level, decision recommendation, and reasons.

Tagline: **See the risk before it becomes a loss.**

## Problem

Payment teams need to detect suspicious transactions quickly without treating every transaction as equally risky. Fraud/risk data is usually imbalanced, so accuracy alone can hide missed fraud. Precision, recall, F1-score, and ROC-AUC are more useful for understanding the tradeoff between false alarms and missed suspicious activity.

## Solution

RiskLens AI demonstrates a practical risk workflow:

Frontend -> FastAPI API -> Risk Engine -> ML Model -> SQLite history/analytics

It is not Razorpay's internal system and does not use private Razorpay data. This prototype uses synthetic transaction data for demonstration purposes.

## Implemented Features

## AI/ML Approach

Features used: transaction amount, transaction frequency, transaction hour, location mismatch, device change, account age, previous transaction count, failed transaction count, international transaction, and unusual transaction indicator.

The training script generates plausible synthetic examples where combinations of high amount, unusual hour, device change, location mismatch, failed attempts, new account age, and unusual behavior increase fraud likelihood. The selected model is saved to `backend/models/risk_model.joblib`.

Risk score calculation:

```text
risk_score = round(model_fraud_probability * 70) + behavioral_signal_points
```

The score is capped at 100. Behavioral signal points can add up to 55 based on explainable rules. Risk levels are:

- `0-29`: LOW -> APPROVE
- `30-69`: MEDIUM -> STEP-UP VERIFICATION / MONITOR
- `70-100`: HIGH -> REVIEW / BLOCK

Explainability is implemented with transparent rule-based reasons, not SHAP.

## Actual Model Metrics

Generated by `python evaluate.py` on the synthetic test split:

- Model: `logistic_regression`
- Decision threshold: `0.72`
- Precision: `0.1938`
- Recall: `0.4032`
- F1-score: `0.2618`
- ROC-AUC: `0.7868`
- Confusion matrix: `[[1334, 104], [37, 25]]`

These are prototype metrics on synthetic data, not real-world fraud performance claims.

## Running Locally

Start the backend:

```bash
cd risklens-ai/backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Start the frontend in a second terminal:

```bash
cd risklens-ai/frontend
npm run dev -- --port 5173
```

Open:

- Dashboard: `http://127.0.0.1:5173`
- API docs: `http://127.0.0.1:8000/docs`
- Health: `http://127.0.0.1:8000/api/health`

## API

- `GET /api/health`

## Demo Flow

1. Open the dashboard.
2. Point out the overview cards, distribution chart, trend chart, recent transactions, and high-risk alerts.
3. In Live Transaction Analyzer, click `Safe transaction`, then `Analyze Transaction`.
4. Click `Suspicious transaction`, analyze again, and compare reasons.

7. Open Swagger at `/docs` and show the same prediction endpoint.

## Actual Challenges Encountered

- The initial package install needed external access because dependencies were not cached.
- A threaded scikit-learn histogram model hit a Windows permission issue, so the stable comparison was narrowed to Logistic Regression and Random Forest.
- Running evaluation at the same time as training caused a CSV race once; rerunning after training fixed it.
- Pytest needed explicit `pythonpath` and test collection config in this workspace.
- The backend originally looked one directory too high for the model; tests caught it and the path was fixed.

## Limitations

- Uses synthetic data only.
- No real payment credentials, real card data, device fingerprinting, or private datasets.
- Explanations are rule-based and transparent, not SHAP-based.
- Metrics are educational prototype metrics and should not be used as production fraud claims.
- SQLite is used for MVP history, not high-volume transaction storage.

## 5-Minute Pitch Script

Hi, I built **RiskLens AI**, an explainable payment risk manager prototype. The goal is to show how a fintech risk team could score a transaction in real time and understand why it was flagged.

The system uses synthetic transaction data, not private payment data. I generate realistic transaction attributes such as amount, time, account age, failed attempts, device change, location mismatch, international transaction, and unusual behavior.

On the backend, FastAPI exposes a prediction endpoint. The ML model returns a fraud probability, and the risk engine combines that probability with transparent behavioral risk signals. The result is a risk score from 0 to 100, a LOW, MEDIUM, or HIGH label, a recommended action, and human-readable reasons.

On the frontend, the dashboard shows total transactions, risk distribution, risk trend, recent transaction history, and high-risk alerts. The live analyzer lets a user load safe, suspicious, or highly suspicious demo transactions and see the score update from the real API.

For evaluation, I compare Logistic Regression and Random Forest on the synthetic dataset. The selected model is Logistic Regression, with ROC-AUC of 0.7868 and F1-score of 0.2618 on the synthetic test split. I focus on precision, recall, F1, and ROC-AUC because fraud-style datasets are imbalanced and accuracy can be misleading.

The important part is explainability. When a transaction is flagged, RiskLens AI explains factors like high amount, unusual time, changed device, failed attempts, or location mismatch. This makes it more useful for a risk analyst than a black-box score alone.

This is a hackathon MVP, not a production fraud engine, but it demonstrates the full end-to-end workflow: data generation, training, evaluation, API prediction, history, analytics, dashboard, and demo mode.
